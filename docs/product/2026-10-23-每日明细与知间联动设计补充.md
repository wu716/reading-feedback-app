# 每日明细与知间联动设计补充

日期：2026-10-23。本文为用户已确认的需求与设计补充。书然端实现与验证见 [项目反馈与周期报告实施记录](2026-10-23-项目反馈与周期报告实施记录.md)；知间业务开发、真实联调与生产部署另行验收。

## 已确认的调整

1. 创建项目页使用“预期结果”，替换草图中的“项目希望带来的结果”。
2. 创建项目和制定本轮计划时均可直接填写阶段任务；原有阶段任务入口继续保留，各入口引用同一任务。任务拆分可选。
3. 反馈规则连接具体日期，支持每天、每周指定星期、选定日期以及临时增补/跳过；采用应用内日历。
4. 每次交付物由用户定义，形式不限于文字；字数只是可选检查标准，不默认要求。
5. 每日反馈沿用现有长期方向的活动明细模型。八个方向均可见，每个方向支持多条具体记录；总量由明细汇总，不退化成每方向只有一个数字输入框。
6. 阅读联动细化到每个日期、每本书的活跃阅读时长，保留书籍身份、来源与可追溯明细。用户可以补记纸书等活动；重复来源不得双计。
7. 每类报告保留项目推进、长期方向、数据完整度和跨期变化。按要回答的问题与数据结构选择图形，不将报告固定为折线图、柱状图或列表的重复组合。

## 每日明细

复用 `static/js/long-term.js` 的 `activityEditor`、`renderActivities` 及 `app/routers/long_term_details.py` 的活动语义：

| 方向 | 具体记录 |
| --- | --- |
| 阅读 | 书名、阅读类型、主主题、补充主题、时长、想法/收获；显示同步或手动来源 |
| 运动 | 运动项目、时长、感受 |
| 帮朋友、陪家人 | 做了什么、时长、补充记录 |
| 写作 | 主题/正在修改什么、时长、新增字数可选、感受与补充 |
| 工作、放松 | 具体活动、时长、补充 |
| 定投 | 标的、金额、补充；不计入时间总量 |

支持新增、修改与移除多条明细。原有活动关联、非计划占用、注意力和消费核对等能力保留。源计时只读，用户想法和分类可补充，修正源时长应保留独立调整依据。缺记、今天没有、尚未核对分别保存。

## 报告呈现

- 日报：项目推进和到期节点；逐书阅读分布、当天活动明细与记录完整度。
- 周报：反馈节点履行与迟交/补交日历、跨日投入和交付变化。
- 月报：记录覆盖日历、方向投入与目标进展、逐书汇总和跨月变化。
- 季度报：阶段结果、里程碑与调整原因；各月投入和交付的变化。
- 年报：全年项目成果目录、阶段演进、投入结构与多年趋势。

这是一组适用原则，不是每页必须堆叠所有图形。图形需匹配单位、样本量、数据完整度与比较目的，允许补充日历、时间线、分布图、结构图或明细。缺记不画成零，时间与金额不混用同一数轴，不把相关变化解释成因果。
