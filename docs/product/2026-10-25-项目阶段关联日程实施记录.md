## 用户确认的范围与实际行为

| 需求 | 实现与验收 |
| --- | --- |
| 在日程取用项目阶段 | “从项目安排”在原输入区下面打开阶段草稿，可选项目与当前／下一阶段，保留原有手动输入和“设计流程”。 |
| 直接编辑当天内容与属性 | 当天文字、熟悉度、难度、重要性、预计分钟同时可编辑，可留空属性、暂不安排、恢复或新增行动；失败保留草稿。 |
| 保留项目来源 | 新日程继续引用同一个项目任务，另外保存调入时的项目、阶段、任务名称及整项估计，不复制出另一套失去关联的项目。 |
| 当天与整项分开 | 当天修改文字、属性、估时和完成状态不修改项目任务；整项改名或验收不回写这些当天安排。旧关联日程继续原有兼容语义。 |
| 阶段无任务也能开始 | 直接写当天行动，原子地建立阶段任务及当天关联；保存仍复用原有当前承诺新增记录。 |
| 跨天继续与反馈 | 草稿显示上次安排／进展；项目任务详情显示“每日推进”。每日完成与项目验收分开，反馈归入所安排日期。 |
| 执行入口保持当天语义 | 新当天安排在执行页打开当天的预演与反馈，“今日目标完成”只完成当天行动，仍保留项目任务及原验收入口。 |
| 条件与重复操作 | 日程可以预先安排待条件任务，开始和完成仍核对条件；下一阶段不会因安排而自动交接。同日重复调入与失败后重试不重复创建；已保存草稿变更后重试、来源移除／移阶段返回冲突。 |
| 用时真实可追溯 | 今日已记录区间按 Asia/Shanghai 午夜切分，另显示项目累计；同一区间只累计一次。自报总用时不写成区间，未记录不表示没有投入。 |

## 存储、兼容与隔离

- 业务数据继续保存在服务器。新增 `daily_project_plans`，与原日程任务一对一关联，`ensure_schema()` 增量建表；不批量改写原日程或项目任务。
- 新表保留来源快照、请求及内容摘要，支持重试去重和已保存内容冲突判断；拆分当天行动继续保留来源。
- 个人导出及服务器 CSV 备份包含新表。历史记录没有新表关联时按旧规则读取，不猜测过去的当天目标或完成情况。
- 保存按用户锁和事务处理，整份草稿先校验；日期／账号切换清空对应可见草稿并隔离迟到响应，跨账号读写由服务端复核。
- 共享工作区其他功能的未提交内容不纳入本次提交。单独组装基于 Git HEAD 的提交快照并运行全量测试，避免依赖其他未提交代码。
