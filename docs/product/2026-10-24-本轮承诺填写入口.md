# 本轮承诺填写入口实施记录

源码版本：2.0.27，Android versionCode 69；网页资源版本：20261024commitment2。源码版本变更不代表已构建、发布此版本 APK；`releases/latest.json` 继续描述已实际发布的既有安装包。

## 入口与实际行为

「项目 → 当前阶段」任务列表上方常驻「本轮承诺」。沿用纸面底色、宋体正文和灰蓝按钮；文本可直接填写、保存草稿、正式确认。确认后直接显示正文，并可打开任务范围和承诺历史；「调整当前承诺」进入既有后果预览及服务端30秒暂停流程。原「当前承诺与调整」入口保留，同样能填写和查看承诺。

草稿保存在服务器的 `stage_commitment_drafts` 表，按阶段隔离，保存时校验用户归属、当前阶段和草稿修订号，防止旧页面静默覆盖另一页面。确认会同时保存文字和当时的任务、估时、完成标准，任务范围变化后需重新核对。已确认文字不能绕过调整流程直接覆盖；空白确认被拒绝，文字上限2000字。

已有范围版本但没有文字时允许补写，追加新版本，不改写旧 JSON。正式开始项目不会自动确认文字草稿；新增当前任务生成范围版本时保留已确认文字；交接到其他阶段不会擅自套用原阶段文字。未开始的草稿调整仍保存为草稿，不冒充正式确认。

## 数据保护与升级

新增草稿表由现有 `ensure_schema()` 幂等创建，不重写旧任务、承诺快照、工作片或阶段记录。文字随已有承诺快照的 `statement` 字段保存，旧快照缺失该字段时显示「未填写承诺文字（历史版本）」。草稿和确认版本均纳入逻辑备份及本人数据导出。没有创建本地业务数据库，没有连接生产业务数据。

按用户约定已删除本次设计的 `design-previews/commitment-entry` 原稿、专用检查页面、清理清单、项目内读取副本，以及两个空目录和不用的本地 Git 排除规则。其他设计示例不在清理范围内。正式实现检查资料保留在 `D:\UserData\ProjectArtifacts\reading-feedback-app\commitment-implementation-20261024`，与已删除的设计示例分开。

## 实际验证

- 整套 Python 测试110项通过，包含草稿恢复、用户隔离、修订冲突、空白与长度限制、历史原文保留、自动版本继承、跨阶段隔离、30秒门槛、已完成列表无强制等待、备份与本人导出及幂等升级。
- JavaScript语法检查和既有项目交互行为测试通过。
- 浏览器操作真实项目页面及真实接口，使用合成账号与 SQLite 内存库，走通「填写 → 保存草稿 → 刷新恢复 → 确认 → 修改文字及任务去向 → 展示后果 → 实际累计30秒 → 确认新版本」，原版本保留。检查了1920、960、390和320像素宽度；承诺卡片和表单均能重排。修正项目页原320px最小宽度在带滚动条窄窗口下产生的横向溢出。
- 本机 `.venv` 中旧版 Starlette TestClient 与 httpx 不兼容，未修改依赖；Python验证使用现有兼容环境。生产 PostgreSQL 升级、Windows WebView2及Android实机、安装包构建发布、生产部署均未在本次冒充完成。
