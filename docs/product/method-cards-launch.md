# 书然 1.5.25：方法卡首发设计

## 产品任务

帮助已经学过或试过方法的人，在类似问题再次出现时，容易找到并试一个具体动作。通过推出可用版本收集实际使用反馈，决定后续设计。已有访谈只是设计线索，尚不代表需求已经得到验证。

## 首发流程

1. 默认进入方法卡首页，未登录可在本浏览器体验。
2. 保存一张卡片：必填「遇到什么情境」和「先做哪一步」；名称、书名和摘录选填。
3. 可从已有行动带入，或从 EPUB 流程类笔记点击「做成方法卡」。先检查情境和动作，再保存。
4. 搜索情境或关键词，遇到问题时点击「遇到了，先试一下」。
5. 实际尝试后点击「试了有帮助」「试了没帮助」或「这次没用上」；原因与备注可选。
6. 根据反馈修改、暂放或恢复卡片；已有尝试保留当时的情境和动作快照。

示例只是写法参考，没有预置成功效果、用户数量或行为成绩。没有强制每日目标、连续打卡处罚或完整日复盘。

## 数据和指标

- 登录用户的方法与尝试存入各自账号，所有读写按当前用户隔离。
- 访客体验卡片只在本浏览器保存。用户登录后可选择导入；稳定 client_key 防止重试重复保存。
- 体验尝试不会导入正式使用指标，避免把示范操作当成真实效果。
- 匿名统计只发送随机浏览器会话标识和体验事件名称，不上传卡片内容、书籍摘录或使用备注。
- 产品意见需用户主动提交，只有站长可以读取意见列表和汇总指标。
- 近 7 天按北京时间自然日统计。访问为浏览器会话数量，并非独立访客人数。
- 「保存卡片的账号」「发起尝试的账号」「记录试过的账号」分别计数。点击开始不等于实际执行。
- 「在不同日期试过」仅指窗口内启动且完成 helpful / not_helpful 反馈，并有至少两个北京时间启动日期的账号，不等于标准 D7 留存。
- 有帮助、没帮助、没用上均来自使用者主观反馈，不是客观疗效或产品因果效应。
- 各项不是同一个获客队列，不能直接相除作为转化率。访客体验和正式账号使用分开显示。
- 私有方法内容不出现在站长市场反馈页面；逻辑备份包含新业务表，注销清理私有方法和尝试快照。

## 兼容和发布

保留原有日程、阅读、行动、Self-talk 和账号能力。手机导航以方法、日程、阅读、记、我的为主，其余工具通过「我的」进入。新表由现有 ensure_schema / create_all 添加，不回写或清空旧业务表。

网页版和 Android 源码版本为 1.5.25 / versionCode 41，静态资源版本 20261010methods1。更新网页后，已有 WebView 可获取新页面；releases/latest.json 继续描述实际已有 APK，不发布虚构下载版本。

发布按 AGENTS.md：检查、提交、推送 origin/main、更新香港服务器并检查 /health。公开宣传时可以直接使用产品首页 #methods；新账号当前仍需一次性邀请码，访客可先体验后再申请。

## 发布后的判断

关注是否有人用自己的情境保存卡片、在真实问题中试过、在不同日期再次使用，并阅读其主动意见。根据这些行为和具体反馈调整产品。没有反馈时，需要结合访问量、注册门槛、入口可见性与使用困难判断原因，不能仅凭未回复或低访问量宣判需求。
