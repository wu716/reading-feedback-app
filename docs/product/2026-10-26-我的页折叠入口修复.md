# 我的页折叠入口修复

## 原因与修改

- 分组初始化在带 `data-i18n` 的标题里创建按钮，但保留了标题本身的翻译标记。页面随后调用 `shuranI18n.apply()` 时，通过 `textContent` 替换标题内容，移除了按钮及事件；折叠内容仍隐藏，用户无法打开。
- 翻译现在只作用于按钮内部的文字节点；标题和动态摘要组成同一个可点击按钮，原内容节点不重建，收起不会清空未保存输入。桌面内容仍保持展开。
- 动态提醒摘要通过状态和语言变更更新，不使用会覆盖时间文本的静态翻译标记。
- 浏览器交互检查同时发现时间选择器创建时引用了已经移除的局部变量 `presets`，导致首次打开抛错；改为从当前弹层取得预设容器。

## 验证证据

`tests/test_me_groups_browser.js` 使用正式 HTML、CSS、翻译脚本、分组初始化及提醒设置代码，在本地浏览器运行；所有接口返回独立合成数据，不连接生产服务。

- 修复前：翻译刷新后按钮数量为 0，预期 5，回归检查失败，与用户截图一致。
- 修复后：五组触摸展开、摘要收起、Enter/Space、重复翻译、中英文切换和窗口变化均通过。
- 密码输入在折叠、翻译及展开后保留；原数据导出按钮事件仍可触发（不代表实际导出文件内容已验证）。
- 提醒开关联动、首次打开时间选择器、快捷时间选择、模拟保存请求及摘要更新通过；23:59→00:00→23:59 和保存 00:00 通过。
- 320、390、768 和 1440px 布局检查通过，无横向溢出和未捕获浏览器异常。
- 另加载完整正式页面及全部正式脚本，保留真实启动、翻译和导航顺序（接口仍为独立合成响应）；五组实际展开、语言切换后再次导航与点击、提醒时间首次打开和取消均通过，无未捕获浏览器异常。
- 既有提醒自动保存与每日提醒 UI 回归检查通过。生产服务、物理手机操作及 APK 构建未在本次验证范围内。
