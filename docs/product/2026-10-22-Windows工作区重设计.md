# Windows 工作区重设计 · 2.0.19

用户在2026年10月22日确认“取消今日，默认日程，独立执行”，选择日程直达方案。本次按这一选择实施，解决此前项目页同时堆叠执行、补记、项目阶段、目标、任务详情、投入历史和流程库的问题。

## 实际范围

- 日程是默认入口。日期选择、当天安排、任务属性、顺序调整各有明确位置。点击任务文字直接编辑；更多信息按“详情”展开。旧“今日”链接转到日程，原月历不再占据首页。
- 执行是独立入口，展示当前任务、时间片操作与本轮顺序。事后补记及时间更正放入“投入记录”，默认执行视图不显示补记表单。原暂停、恢复剩余时间、到点结算及条件核对沿用已有接口。
- 项目只呈现交付结果、阶段、任务及其开始条件。当前阶段、下一阶段、已结束阶段分模式查看；项目状态变更按需展开。近期目标管理收起为独立辅助区域，选中任务后才显示详情。
- 流程库有独立入口，新建和编辑才打开表单。使用流程时必须明确选择日程日期，或项目和阶段；不默认投放到页面后台选中的第一个项目。
- 共用固定左侧导航与浅底、深色正文、蓝色强调色。窄窗保留有文字的导航，手机通过上方工作区入口切换，原底栏保留。

URL使用同一份项目模块的独立视图：`projects.html`为项目，`projects.html?view=execution`为执行，`projects.html?view=templates`为流程库。可直接打开、刷新及前进后退；旧`#execution`、`#templateTitle`和原任务深链接继续可用。共用模块不意味着把各工作区内容同时展示。

## 数据与兼容

1. 增量增加`daily_tasks.legacy_todo_id`及唯一索引，通过原待办ID建立一对一关联，不按任务文字去重。旧记录第一次查看该日时接入日程；旧客户端新建的待办立即接入，快捷记下的旧待办也会在读取该日时接入。原日期、创建时间、完成状态及提醒ID保留，原记录不删除。
2. 日程和旧待办接口的编辑、完成与删除同步到关联记录。旧提醒接口及原生提醒同步继续使用原ID；提醒时间变更重置发送状态。完成操作沿用当前开始条件／交付规则，关联项目需走项目验收，旧客户端不能绕过。
3. 项目改名与验收同步其日程引用及提醒。软删除保留历史工作片；项目任务和日程不重复计算实际投入。
4. 日程实例新增步骤、普通检查项、常见难点及验收标准快照字段。流程后续修改不追改已生成内容或勾选状态。将日程纳入项目时迁移这些内容及勾选状态，之后在项目任务管理步骤与检查，原投入关联保持。
5. 迁移可以重复执行。旧项目启动条件、估时、预演、工作片、模板及其他历史内容不改写。本人导出自动包含新列；逻辑备份增加完整日程、日程日期及旧待办历史，保留关联和提醒字段。
6. 本地验证仅使用SQLite内存库和示例账号，没有使用或创建本地业务数据库。截图及临时脚本位于`D:\UserData\ProjectArtifacts\reading-feedback-app\windows-design-review-20261022`。
