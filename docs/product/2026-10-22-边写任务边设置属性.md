当前源码 **2.0.24**，Android源码 **versionCode 66**，网页资源 **20261022hierarchy1**。本轮基线提交 `4b17e86`，仅修正分组层级、控件外观、无障碍语义和极窄窗口适配，业务接口与数据库不变。2.0.23已实现边写边设置、灰蓝配色和「设计流程」入口；此前计划、训练、30秒调整和完整反馈能力继续保留。

## 分组层级与可点击性（2.0.24）

保留「重要性」原名与「不重要／一般／重要」选项，不改名为优先级。熟悉度、难度和重要性分组标题置于上方，使用12px灰色文字；可选项置于下方浅灰蓝分段控件，使用14px墨蓝文字。未选中时也有组边界，悬停、键盘焦点、选中分别提供反馈，选中项保留灰蓝底色与内边线。标签使用非交互文本，按钮保留原生键盘操作，并通过具名分组和 `aria-pressed` 表达所选状态。

预计用时采用相同上下层级和输入边界。已保存任务的熟悉度、难度同步使用分段控件，重要性摘要仍是普通文本。控件有意设计为同组共用一个浅色边界，没有使用浏览器默认白底黑边按钮或复选框。320像素窄窗口下任务输入允许收缩，消除输入行的横向溢出。

## 用户要求与交互

写任务的同时就能设置属性。文字输入、熟悉／陌生、简单／困难、重要性、预计用时在同一输入区常驻显示，可以写几字、标记属性、继续写、再改时间，自由交替操作，没有先后顺序。不要求先写完文字或先选完属性，不折叠设置，也不要求添加后再补设。

属性均可留空；再次点击已选标记可取消。按文字输入框或预计用时输入框中的回车，或点「添加」，保存当时的文字和属性。中文输入法选字的回车不提交。保存成功后清空输入区，已添加任务仍可直接修改标题、熟悉度、难度和用时；重要性修订及完整历史继续在「更多」中打开。实际用时在执行后反馈。

沿用纸面、宋体任务文字和蓝色链接。添加按钮为墨蓝，选中标记为灰蓝底、墨蓝字，保存用时和完成状态使用同一蓝色；移除日程常规操作的红色强调。流程设计的拖动标记同步使用灰蓝。顶部「调整顺序」改为「设计流程」，进入后显示「完成设计」，继续支持先后顺序和并行关系。

## 存储与兼容

创建任务的原有POST接口增加可选的 `difficulty`、`importance` 字段，与文字、熟悉度和估时在一次数据库事务中保存。使用既有DailyTask和TaskPractice存储，无新增表或迁移。首次重要性标记保留初始时间与值，执行时可进入原有快照；不将首次标记冒充事后审视。

难度和重要性使用现有业务枚举并校验，非法值返回422且不留下半条任务。只传文字的旧客户端继续可用。熟悉度、难度和目标重要性分别存储，历史 `priority` 优先级不映射为新重要性；既有估时历史、实际投入与反馈记录保持原有语义。

```bash

cd deploy/aliyun
docker compose up -d --build
if health_json="$(curl -fsS --retry 30 --retry-all-errors --retry-delay 2 --retry-max-time 90 --connect-timeout 3 --max-time 5 http://127.0.0.1:8000/health)" &&
   printf '%s\n' "$health_json" | python3 -c 'import json,sys; r=json.load(sys.stdin); print(json.dumps(r,ensure_ascii=False)); sys.exit(0 if r.get("version")=="2.0.24" and r.get("ui_version")=="20261022hierarchy1" else "版本验证未通过")'
then
    echo "部署验证通过"
    docker compose ps
else
    docker compose ps
    docker compose logs --tail=100 app
    exit 1
fi
SHURAN_DEPLOY
```
