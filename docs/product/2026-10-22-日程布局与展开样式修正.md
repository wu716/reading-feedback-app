## 对应用户截图的修正

1. 侧栏与正文使用同一纸面底色和纹理，保留原有宋体任务文字、蓝色链接与朱红强调。缩小日程标题，正文限定960px阅读宽度；日期工具栏靠近日期。任务操作移到用时下方，全部与所属任务左对齐，不再把短任务的按钮推到页面最右侧。
2. 更多区域的按钮统一去掉浏览器默认外观、白底、黑边和阴影，按「准备与回顾」「归属与开始」分组。反馈输入使用纸面下划线，删除单独呈现；保留键盘焦点提示和鼠标悬停提示。
3. 「拆开」只出现下一步输入并聚焦，可按回车或点加入；「更多」单独展开。此前 `expandedTasks.has(task.id) || splitFor === task.id` 使拆分顺带显示整个高级区域，已取消这一耦合。用户主动同时打开两者仍可并列保留。下一步草稿在当前页面按任务、日期保留，切换更多或收起再展开不清空输入，加入子任务后才清空该草稿；关闭或刷新网页前仍需保存。
4. 回车直接添加、点标题修改、熟悉度和容易／困难、预计／实际用时、所有计划训练入口及任务历史继续保留；目标重要性、熟悉度和难度没有合并或改写语义。

## 部署与启动等待

PowerShell登录服务器：

```powershell
ssh ubuntu@43.161.238.165
```

Ubuntu内完整执行以下一段。root权限同时处理仓库与`.env`访问；仓库信任例外只对这次Git命令生效。健康检查覆盖启动中的连接重置，成功拿到响应后才解析版本；仍失败则输出状态和应用日志。

```bash
sudo bash -e -o pipefail <<'SHURAN_DEPLOY'
cd /opt/shuran-app
git -c safe.directory=/opt/shuran-app pull --ff-only origin main
cd deploy/aliyun
docker compose up -d --build
if health_json="$(curl -fsS --retry 30 --retry-all-errors --retry-delay 2 --retry-max-time 90 --connect-timeout 3 --max-time 5 http://127.0.0.1:8000/health)" &&
   printf '%s\n' "$health_json" | python3 -c 'import json,sys; r=json.load(sys.stdin); print(json.dumps(r,ensure_ascii=False)); sys.exit(0 if r.get("version")=="2.0.22" and r.get("ui_version")=="20261022balance1" else "版本验证未通过")'
then
    echo "部署验证通过"
    docker compose ps
else
    docker compose ps
    docker compose logs --tail=100 app
    exit 1
fi
SHURAN_DEPLOY
```

代理仅完成本地验证、提交和GitHub推送，生产部署由用户执行。新资源生效后重开现有Windows程序核对界面，不能以源码或镜像构建成功代替实际客户端验收。
