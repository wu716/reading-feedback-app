# 知间 0.1.16 ↔ 书然 2.0.26：接收端协议与配置

本次接收端已对齐知间项目实际新增的来源协议：`D:\projects\reader-app\docs\书然阅读同步协议-v1.md`。采用服务器拉取和两边账号明确确认，不要求知间改成另一套推送接口。源码和合成协议测试不代表服务器已部署或真实账号已联调。

## 管理员配置

| 书然服务器环境变量 | 对应知间服务器配置 |
| --- | --- |
| `READER_API_URL` | 用户已配置的知间 HTTPS 地址，或受控本机 SSH 通道。只能由管理员设置，浏览器没有任意来源 URL 输入框。 |
| `READER_CLIENT_ID` | 与知间的 `SHURAN_CLIENT_ID` 相同 |
| `READER_CLIENT_SECRET` | 与知间的 `SHURAN_CLIENT_SECRET` 相同，至少 32 字符强随机值，仅服务端保存 |

未配置时页面明确显示尚未配置，可继续手动记录。机器请求带 `X-Shuran-Client` 和 `Authorization: Bearer <机器凭证>`；阅读请求另带 `X-Reading-Grant: <单账号阅读令牌>`。生产禁止明文远程 HTTP、URL 内嵌凭证、任意跳转和用户提供的携密目标。

书然使用稳定随机接收账号标识，不拿两个数据库的数值主键做身份匹配。nonce 和阅读令牌使用由书然 `SECRET_KEY` 派生的 Fernet 密钥加密后仅存服务器；不会返回浏览器、普通导出或日志。请保管服务端密钥，变更密钥后现有加密授权需重新关联。

## 用户确认流程

1. 登录书然，点击每日反馈中的“生成 10 分钟关联码”。书然从当前会话取得账号身份，服务端调用知间 `POST /api/integrations/shuran/v1/link-requests`，保存 nonce，只向用户显示码、有效期和书然账号标签。
2. 登录知间，在“关联书然”页输入此码，核对接收账号，选择真实可用起始日期、私密书名/别名并确认。此时仍未完成书然侧授权，也没有可读取令牌返回浏览器。
3. 回书然点击“已在知间确认，读取账号信息”。书然服务端调用来源 `.../link-requests/{id}/status`，页面明确展示两边账号、授权起始日期及私密选项。
4. 用户点击“确认关联这两个账号”。书然将用户刚核对的来源实例与来源账号传给来源 `.../confirm`，核对响应中的来源、接收账号和范围后保存受限阅读令牌。不能后台自动跳过最终确认。
5. 首次同步可立即触发，随后生产调度器每 5 分钟自动读取，不依赖浏览器继续打开。用户可查看状态、手动重试或停止关联。

相同来源账号不能自动接管另一个书然账号。重试、过期、旧请求、错账号、错误来源、重复消费均拒绝。确认响应丢失或跨服务保存失败时，重新发起关联，不能再次领取已消费令牌。

书然停止关联会清除其读取凭证并立即停止新同步，已接收历史保留。知间中的授权可以在其本人关联页撤销；来源返回 403 时书然也停止并清除令牌。彻底删除历史另需用户明确操作。

## 书然前端调用的接口

以下接口全部要求当前书然账号登录：

| 方法和路径（均以 `/api/integrations/reader` 开头） | 含义 |
| --- | --- |
| `POST /pairing` | 发起来源请求；返回 `pairing_id`、关联码、有效期，绝不返回 nonce |
| `GET /pairings/{pairing_id}` | 读取知间确认状态，持久保存用户待核对的公开账号信息 |
| `POST /pairings/{pairing_id}/confirm` | 提交 `expected_source_instance_id` 与 `expected_source_account_id`；核对通过后返回绑定 ID，绝不返回阅读令牌 |
| `GET /status` | 本账号关联、授权状态、最后读取时间和失败原因 |
| `POST /bindings/{binding_id}/sync` | 本人手动同步；每批最多读取 3 页，其余由服务器继续追赶 |
| `DELETE /bindings/{binding_id}` | 停止同步并清除凭证，保留历史 |

## 快照、游标与兼容

书然服务端调用知间 `GET /api/integrations/shuran/v1/reading-days`，`from` 固定为确认的授权日期，`to` 不设置以持续开放上界，`limit=31`，后续携带已保存的 `cursor`。来源的核心响应为：

```json
{
  "schema_version": 1,
  "source_instance_id": "稳定来源实例 UUID",
  "source_account_id": "稳定来源账号 UUID",
  "receiver_account_id": "书然明确授权的接收账号标识",
  "timezone": "Asia/Shanghai",
  "reading_detail_started_at": "2026-10-23T00:00:00+08:00",
  "days": [{
    "date": "2026-10-23",
    "revision": 42,
    "snapshot_kind": "full_day",
    "active_seconds": 2700,
    "coverage": "recorded_not_day_confirmed",
    "books": [
      {"source_book_id": "book-a", "title": "示例书甲", "active_seconds": 1800, "document_deleted": false},
      {"source_book_id": "book-b", "title": "示例书乙", "active_seconds": 900, "document_deleted": false}
    ],
    "removed_book_ids": [],
    "deleted": false
  }],
  "high_watermark": 42,
  "next_cursor": null,
  "checkpoint": "来源签名的不透明检查点",
  "coverage": "recorded_not_day_confirmed",
  "pending_tail": "client_memory_not_observable"
}
```

- 校验两端账号与来源实例，校验日总量等于逐书秒数之和、不超过 86400、日期在实际记录与授权范围内、日修订不超高水位。
- 只接受完整日快照。更高修订替换旧版本，重复和乱序不累加；同修订不同内容报错。单页来源快照、阅读待核对状态和游标在同一事务提交，失败页不推进进度。
- 有 `next_cursor` 继续当前分页；结束后必须保存 `checkpoint`。空 `days` 代表无变化，不生成零阅读日。游标无效/过期时重新完整读取，已有数据仍按修订号去重；不丢历史或自动清空账本。
- 接收 `removed_book_ids`、`deleted` 与 `document_deleted` 的实际来源语义。完整空日快照只移除该日源时长；原文档删除的书仍保留已发生阅读，不能按此标志删除历史活动。
- 来源活跃时长只读；分类/主题/收获在书然补充。手动补记独立保留，可与同一段知间阅读建立核对引用，不重复计时。源数据变化会使阅读方向待重新核对，其他方向不受影响。
- 来源 0.1.16 不把未知日期的累计基线导出为日数据。书然不编造过去每日曲线；将来若来源提供独立 `historical_baseline`，接收端只展示基线，不计入每日/周期投入。
- 401/403、游标错误、网络失败和不合规数据都显示同步异常，保留已接收历史，不当作“本日没有阅读”。失败后自动退避；403 停止失效授权，其余可手动重试。单页上限 10 MB。

## 验证边界

接收端合成测试覆盖双向确认、凭证不进入前端、本人归属、逐书替换、重复/乱序、旧游标恢复、删除语义、手动去重、迟到同步导致旧草稿冲突及报告更新。生产 SMTP、真机锁屏、两端真实用户账号和服务器部署仍需实际环境验收。来源端计时、并发裁决及客户端退出尾段限制，以知间 0.1.16 的交付记录为准。
