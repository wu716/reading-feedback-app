# 项目、阶段与任务删除和恢复

本次版本：2.0.38，Android 源码 versionCode 80；APK 版本号只更新源码，不改写已有安装包的发布元数据。

## 已实现的范围

- 项目名旁、阶段标题旁和任务行分别提供直接可见的删除入口；“已删除”按项目、阶段、任务查看和恢复。
- 删除前由服务器计算子内容、未完成日程、轮转项、已发生投入、正在进行的计时和外部依赖；确认时重新核对范围，变化后必须重新预览。
- 整项目或阶段包含本次仍在使用的子内容；只对本批次标记的行进行恢复，不带回先前单独删除的任务。
- 当前承诺的范围缩减沿用服务端30秒可见暂停、同窗口租约及变更校验，原因和原范围留痕；不将删除当作完成、交付或验收。
- 关联未完成日程及未完成子项移出待办，暂停旧待办提醒并移出轮转；已完成日程、投入区间和反馈历史保留。已完成子日程的上级删除后，仍可在原日期查看。
- 正在工作的任务先明确结束计时；暂停的相关任务删除后清除可恢复计时指针，历史片段保留。
- 外部任务或项目仍依赖删除对象时先阻止删除，提供原条件入口；在原条件流程处理，不借删除自动解除或满足依赖。
- 恢复默认不恢复日程、计时、轮转或提醒。日程可以逐条选择恢复，过去的未完成日程重新选日期；同一任务同一天已有安排时阻止重复恢复，失败保持事务回滚。
- 删除当前阶段不会自动推进下一阶段；没有当前阶段时可主动交接。恢复原当前阶段若已有替代，须明确将原阶段恢复为下一阶段。

## 数据与兼容

业务数据仍在服务器。本次增量增加 `project_stages.deleted_at` 和 `project_deletions` 批次表，启动时幂等创建；旧阶段默认未删除，不清空或重写旧表。项目、任务及日程继续沿用已有删除标记。

删除批次和阶段标记纳入整库备份及账号范围导出。批次保存预览范围、指纹、原因、暂停状态、删除及恢复时间。不同账号不能查看、确认或恢复彼此的批次。历史投入继续使用原任务身份，并显示“来源已删除”；没有任务名称快照的旧片段从保留的任务行补齐展示名称。

项目整体删除时关闭该项目反馈节点的提醒、取消尚未发送的相关邮件并收起未处理通知；提醒历史和成果保留。恢复项目不会自动重新开启这些提醒。

## 用户执行服务器更新

Windows PowerShell 登录：

```powershell
ssh ubuntu@43.161.238.165
```

Ubuntu 登录后执行。先备份数据库；不会删除 Docker 数据卷：

```bash
sudo -i
set -e
cd /opt/shuran-app/deploy/aliyun
install -d -m 700 /var/backups/shuran
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > "/var/backups/shuran/before-project-deletion-$(date +%Y%m%d-%H%M%S).dump"
cd /opt/shuran-app
git pull origin main
cd deploy/aliyun
docker compose up -d --build
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/ready
```

若容器仍在启动，稍后重试健康检查；失败时在上述 compose 目录执行 `docker compose ps` 和 `docker compose logs --tail=120 app` 定位。不要运行 `docker compose down -v`。本次没有执行生产部署或发布新 APK。
