# Windows 连接恢复与轻量就绪检查

## 范围与版本

Windows 桌面端更新为 **1.6.4**，Web/API 沿用当前源码 **2.0.27**。本次不更新安卓壳：现有已发布元数据为 **2.0.26 / versionCode 68**，Android 源码的 **2.0.27 / versionCode 69** 由其对应更新另行发布，本次不构建或宣称发布新 APK。网页缓存标识在本次提交中递增为 `20261024recovery1`。

源代码、GitHub 推送、本地安装包、生产部署是独立状态。香港生产服务器由用户执行部署，代理不执行。服务器更新不会替换用户电脑上的 Windows EXE，已有用户需要安装新客户端。

## 客户端行为

- 本地原生失败界面使用纸面背景、灰蓝和墨蓝，窄窗口自动换行，诊断可展开。
- 首次 GET 遇到临时网络错误及 HTTP 408/502/503/504，按 2、5、10 秒间隔，最多自动重试三次。单次首次加载最多等待 15 秒。
- 手动重新连接开启新一轮有限尝试；停止按钮和窗口关闭会取消待执行的重试。证书、401/403/407、其他非临时 HTTP 错误不自动重试，不忽略证书错误。
- 只重试客户端主动发起的首页 GET 及同一导航的重定向，不重放后续导航、表单或保存操作；网页成功加载后不会因为 API 请求失败而自动整页刷新。
- 本次不实现跨关闭草稿缓存或离线写入队列，也不修改系统代理。
- 诊断仅在当前进程内显示时间、客户端版本、状态码和重试次数，无额外磁盘日志，不包含任务正文、URL 查询参数、登录令牌或代理密钥。
- 修正原有更新器的 JSON 字段映射；旧 1.6.3 更新器自身的字段映射问题无法由服务器更新修复，需手动下载新版。

## 服务器成本与边界

新增 `/ready`，在 FastAPI 原有线程池内执行只读 `SELECT 1`。连接检查使用短超时且每次关闭，不增加常驻数据库连接；Docker 每 30 秒检查一次，无额外软件包、监控容器、业务表或迁移。

`/health` 保留既有格式，表示进程可响应。`/ready` 在数据库不可用时返回 HTTP 503，可用时返回 200，不暴露连接凭证。Compose 改用 `/ready`；PostgreSQL 健康检查补充实际数据库名，避免默认连接到错误数据库。

应用、数据库各设置最多 3 份、每份约 5 MB 的 Docker `local` 日志并使用其默认压缩。两容器日志目标容量合计约 30 MB，另有少量索引等开销；该限制不覆盖 Nginx、宿主系统或其他项目日志。安装包替换已有文件，约 48.8 MiB，不新增常驻服务。

健康检查会标出异常，**不等于 Docker 会因 unhealthy 自动重启**。本次不安装自动重启脚本或外部告警服务。

## 部署（用户执行）

先把本地已验证的 Windows 安装包传到服务器暂存目录。Windows PowerShell：

```powershell
cd D:\projects\reading-feedback-app
Get-FileHash -Algorithm SHA256 D:\UserData\ProjectArtifacts\reading-feedback-app\windows-1.6.4-final\shuran-windows.exe
scp D:\UserData\ProjectArtifacts\reading-feedback-app\windows-1.6.4-final\shuran-windows.exe ubuntu@43.161.238.165:/tmp/shuran-windows-1.6.4.exe
ssh ubuntu@43.161.238.165
```

登录后在 Ubuntu 执行以下完整代码块。校验通过后只替换安装包，不操作数据库及上传资料卷。日志设置变化会重新创建相关容器，部署期间可能短暂不可用。

```bash
sudo -i
set -e
cd /opt/shuran-app
git pull --ff-only origin main
python3 - <<'PY'
from pathlib import Path
import hashlib, json
package = Path('/tmp/shuran-windows-1.6.4.exe')
meta = json.loads(Path('/opt/shuran-app/releases/windows-latest.json').read_text())
assert meta['versionName'] == '1.6.4', 'Unexpected Windows release metadata'
assert package.stat().st_size == meta['size_bytes'], 'Package size mismatch'
digest = hashlib.sha256()
with package.open('rb') as source:
    for chunk in iter(lambda: source.read(1024 * 1024), b''):
        digest.update(chunk)
assert digest.hexdigest() == meta['sha256'], 'Package SHA-256 mismatch'
print('Windows 1.6.4 package verified')
PY
chmod 644 /tmp/shuran-windows-1.6.4.exe
mv /tmp/shuran-windows-1.6.4.exe /opt/shuran-app/releases/shuran-windows.exe
cd /opt/shuran-app/deploy/aliyun
docker compose config --quiet
docker compose up -d --build
curl --retry 12 --retry-delay 3 --retry-all-errors --retry-max-time 90 --connect-timeout 5 --max-time 10 -fsS http://127.0.0.1:8000/health
curl --retry 12 --retry-delay 3 --retry-all-errors --retry-max-time 90 --connect-timeout 5 --max-time 10 -fsS http://127.0.0.1:8000/ready
docker compose ps
curl -fsS http://127.0.0.1:8000/download/info | python3 -c 'import json,sys; d=json.load(sys.stdin); print({k:d.get(k) for k in ("windows_available","windows_version","windows_size_bytes")}); assert d.get("windows_available") and d.get("windows_version")=="1.6.4"'
```

如果只运行 `git pull` 而没有上传匹配的新 EXE，Windows 下载会暂时不可用，避免把旧包伪报成 1.6.4。保留原已安装客户端的正常使用。部署失败时先获取证据，不反复重启数据库：

```bash
cd /opt/shuran-app/deploy/aliyun
docker compose ps
docker compose logs --no-color --tail=100 app db
curl --connect-timeout 5 --max-time 10 -i http://127.0.0.1:8000/health
curl --connect-timeout 5 --max-time 10 -i http://127.0.0.1:8000/ready
```
