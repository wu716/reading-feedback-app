# 长期目标明细与报告 · 2.0.11

版本：`2.0.11`；Android `versionCode 53`；静态资源版本：`20261020ledger1`。

## 记录与交互

保留米白底、深蓝文字和低饱和分类颜色。桌面左侧记录活动，右侧记录消费；手机改为上下排列。每天每个方向都可添加多条记录，常用内容提供最近记录提示。感受和补充主题放在可展开区域，减少初次填写负担。

| 板块 | 记录字段 |
| --- | --- |
| 阅读 | 可选书名、虚构／非虚构／未分类、主主题、时长，可选补充主题和收获 |
| 运动 | 运动项目、时长，可选运动感受 |
| 帮朋友 | 具体事情、时长，可选补充 |
| 陪家人 | 陪伴内容、时长，可选感受 |
| 定投 | 标的、金额，可选备注；不累计时间，不计入消费 |
| 写作 | 主题或修改内容、时长，可选新增字数和补充；构思、修改可填 0 字 |
| 工作 | 工作内容、时长，可选补充 |
| 放松 | 具体活动、时长，可选感受 |

非计划占用是活动上的可选标记，时长仅计算一次，不评价某种活动是否“有价值”。时间日志可以归类并关联，之后时长随源日志变化；源日志被移除或改到其他日期时保留描述并提示，停止计时，可以转为手动记录。

## 阅读地图

- 类型和主题独立：一本虚构作品同样可以涉及历史、社会、心理等主题。
- 主题包括文学与语言、历史与传记、哲学与思想、心理与自我认识、社会与文化、自然科学、技术与工程、商业与经济、艺术与审美、健康与生活、教育与成长，以及其他、未分类。
- 一个主主题承担整条记录的时长，确保各主题之和等于阅读总时长。最多 5 个补充主题按涉及记录数统计，允许重叠。
- 最近同名书籍可带入上次分类，用户可以修改。当前采用有限的固定阅读主题；消费类别支持自定义。
- 地图展示已记录的阅读选择，不把有限记录解释成人格或能力。记录数不等于读完的书籍数量；历史汇总也只是一条记录。

## 消费记账

默认类别：餐饮、交通、居住与水电、日用购物、学习成长、医疗健康、娱乐休闲、社交人情、其他。历史总额归入“历史未分类”，不猜测用途。

支持消费、退款、备注、同日活动关联和一笔拆成两笔。拆分后总金额保持不变，可分别更改分类。消费类别可增添、改名、停用；停用后仍保留历史账目归属。

- 金额以整数分保存和计算，最多两位小数。
- 净支出 = 消费 − 实际到账退款；退款归入到账日期。退款可以使当日某类别净支出为负。
- 报表占比采用消费总额作为分母，退款单列，避免负金额扭曲比例。
- 消费分类可点击查看明细；关联账目和活动支持双向查看。
- “确认当天没有消费”和“尚未记录”分别处理，不将漏记默认为零支出。

## 五种报告和目标

日报、周报、月报、季报、年报采用北京时间自然周期，周一开始。未来日期不计入已过天数；当前周期只汇总到今天。

每种报告都提供各板块明细及汇总、阅读类型与主题分布、写作字数、定投标的及金额、各消费类别消费／退款／净支出／占比。周月趋势按日，季年趋势按月；记录足迹可点击补记。

上期对比明确标注两边的等长区间。当上月较短时按较短月份天数比较，完整本期总额仍独立展示。报告提示核对天数，避免把漏记当作生活方式变化。

目标可按周、月、季、年设置时长、记录条数、字数、定投金额；消费预算可按类别设置。阅读目标可限定类型和主主题。目标有开始和可选结束日期，进度按目标自身周期计算。

## 存储与兼容

- 数据按账号隔离，写入现有服务器数据库。新增 `long_term_ledger_days` 和 `long_term_preferences` 两张表，由现有幂等启动流程自动创建，无需手工改旧表。
- 旧记录先在读取时转换为兼容视图，首次保存才写入新明细表；原表保留。旧消费总额、旧定投金额和旧注意力记录不丢失。
- 旧定投时长保留在原数据中并提示，新统计只累计投资金额。
- 升级后的日期拒绝旧客户端写入，避免旧总额覆盖新明细。
- 每日活动与消费原子保存；版本号校验防止多页面互相覆盖。保存冲突或失败保留当前会话草稿，并提供 JSON 导出和重新读取。
- 草稿仅在当前页面会话保留，关闭页面前会提示；正式报表仅统计服务器已保存数据。导出 JSON 用于留存，不提供自动导入。
- 逻辑备份包含两张新表。本地测试与页面预览仅使用内存数据库，不创建真实业务数据库。

## 部署

由用户执行生产部署。先确认 GitHub `Build Android APK` 成功，`android-2.0.11` Release 包含签名 APK，且 `releases/latest.json` 已更新为 53 / 2.0.11。

Windows PowerShell：

```powershell
ssh ubuntu@43.161.238.165
```

Ubuntu：

```bash
sudo -i
cd /opt/shuran-app
git pull --ff-only origin main
bash deploy/aliyun/upgrade-2.0.11.sh
```

脚本校验 Release 标题、SHA-256、APK 包内版本与下载元数据，备份现有 APK 及数据库，然后执行 `docker compose up -d --build`、健康检查和下载信息检查。不会删除数据卷。若任一步失败会停止并显示错误；不要使用重建空库或删除数据卷作为补救。
