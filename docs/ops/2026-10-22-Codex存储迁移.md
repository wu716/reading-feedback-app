## 已确定的存储规则

- `D:\projects`：独立项目。
- `D:\Applications`：独立软件及开发工具，如 Android SDK、Rust 工具链、Python、Node 全局工具和 Codex 辅助程序。
- `D:\UserData\DevTools`：Gradle、Cargo、NuGet、npm、pip 等开发资料与缓存。
- `D:\UserData\Codex`：原 `.codex` 中的配置、会话、插件、记忆和本地状态。
- `D:\UserData\CodexPackageCache`：Windows 商店版 Codex 的实际 `LocalCache` 数据，其中包含界面缓存与 uv 缓存。
- `D:\UserData\Temp`：新的用户级 `TEMP`、`TMP` 文件。

旧 C 盘路径可以保留为目录联接。日志显示旧路径时，检查 `LinkType` 与 `Target`，不能据显示路径判断文件的物理存储位置。

## 迁移方法与保护

脚本只处理明确列出的当前用户目录，不迁移整个 Windows 用户资料夹、注册表账户配置或系统目录。先复制并校验所有文件的 SHA-256，确认源文件在复制期间未变化，再短暂重命名原目录并建立旧路径到 D 盘的联接；再次校验通过后才清理已被验证复制的原副本。复制和校验失败时保留原目录，不执行镜像删除、强制覆盖或进程终止。

跨盘时，将源目录的有效访问规则保留为目标的受保护规则，避免继承 D 盘较宽的默认权限；子项的特殊访问规则另行保留。迁移 `.codex` 前，对 SQLite 文件执行只读完整性检查，并通过 SQLite backup API 在维护目录保存独立备份。

商店应用可能把新建的 AppData 副本名重定向到本应用的 `LocalCache`。脚本只接受已核对的对应路径；清理前仍核验全部文件。已迁移目录在 `LocalCache` 中留下的已知联接按联接保留，不重复复制其目标数据，不遍历删除联接目标。

`state.json` 记录每项目标、状态和原因；`summary.json` 记录本轮释放空间及完成数量；`environment-before.json` 保留所改用户环境变量的原值。只有 `migrated` 表示该目录已切换且校验通过，`pending-exit` 表示尚待退出相关程序；不能把准备好脚本当成完成全部迁移。
