# 提醒自动保存与荣耀后台恢复

版本：2.0.44，Android versionCode 86。

## 问题与证据

用户所说的“重启”是划掉后台后重新打开书然。USB 排查发现荣耀 ELI-AN00（Android 16）将划掉后台记为 `SystemManagerSwipeUp / FORCE STOP`。初始状态下无障碍服务虽已绑定，系统只有后台轮询闹钟，没有每日记录闹钟。

手机原安装 2.0.38/versionCode 80。实际安装包与源码均存在荣耀设置跳转使用华为旧类名、登录凭证变化清除本地每日提醒的问题。设置页面读取失败还会用缺少每日提醒字段的默认对象覆盖显示。后两项是证实存在的代码风险，未把它们当成这次现场丢设置的唯一根因。

## 实现

- 提醒开关及时间在 change 后自动保存，串行发送、合并未发送的旧改动；保存时保留所填内容，显示保存状态和失败重试，不再保留需用户寻找的保存按钮。
- 以保存接口返回值直接同步 Android，并区分服务器失败、原生同步失败和旧壳无法确认同步结果。原生确认表示设置持久化和调度调用完成，不证明将来通知必达。
- 读取失败禁用编辑并允许重试，不伪造“关闭”。前端和原生均防止较早请求回写覆盖新设置。
- 同账号 JWT 更新保留本地每日提醒；暂时空凭证不充当退出。明确退出、换账号仍清理个人提醒。同账号判断仅隔离本地偏好，不用于 API 认证。
- 原生恢复同时考虑已保存的每日提醒，不再只以本地待办判断是否需要恢复。
- 新增荣耀实际存在的启动管理类名，保留旧地址兼容；无障碍解绑调用系统父类清理。
- 沿用暖纸色、墨蓝/灰蓝和原提醒区域布局，提示修改后自动保存；说明划掉后台可能被强行停止。
- 无服务器业务表变更、无数据库迁移、无业务数据删除。

## 手机实际操作与验收

覆盖安装签名 release 2.0.44，未卸载、未清除数据。将书然从荣耀自动管理改为手动管理，确认允许自启动、关联启动、后台活动三项均开启。

再次打开书然后系统出现每日记录主闹钟及备份闹钟，下次时间为 2026-10-27 18:13（沿用现场已保存时间，非本次擅自设定）。从最近任务单独划掉书然，再返回桌面，系统 `stopped=false`，书然进程、无障碍绑定与每日记录闹钟仍保留。用户随后以实体音量加三击确认“已打开记”。没有操作其他应用的后台卡片。

- 既有每日记录前端行为检查通过。
- 后端每日记录回归 17 项通过，APK 发布守卫 8 项通过。
- Android 单元测试 16 项通过（按键 8、记录时间 5、分类 3）；release 构建与 lintVital 通过。
- HTML 内联脚本语法检查通过。独立浏览器示例使用正式提醒区与实际保存函数、合成接口，验证正在保存、失败重试、重试后已保存状态。

## 范围与待办

当前手机已装新原生壳；自动保存网页需用户部署服务器代码后生效。每日提醒仍未进行下一次自然到点实发、锁屏到点、整机重启或长时间待机验收。应用无法绕过系统明确强行停止，手动管理的效果仅对这台设备现场划掉测试得到证明。
