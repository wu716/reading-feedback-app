# 书然协作手册

## 2026-10-22：Windows 工作区职责与默认入口

用户确认取消独立“今日”，Windows 默认进入当天“日程”，并将“执行”“项目”“流程库”作为独立入口。日程安排日期与顺序；执行只处理当前任务、计时和本轮顺序，补记与更正放入“投入记录”；项目管理交付结果、阶段和任务；流程库独立管理可复用的方法。后续不得再把流程库、目标长表单或事后补记表单常驻叠加到执行区。

项目任务安排到日程继续引用原任务；从流程模板生成任务才创建独立实例。旧待办接入日程必须保留日期、提醒、完成状态和来源关系，不按名称猜测合并。实施与部署说明见 [Windows工作区重设计](../product/2026-10-22-Windows工作区重设计.md)。

## 2026-10-22：计划、执行与反馈设计交接入口

本次完整设计见 [计划执行与反馈设计交接](../product/2026-10-22-计划执行与反馈设计交接.md)。文档保留原始七项需求，第1项包含估时反馈与心理建设，另以第8项覆盖项目及任务的启动条件、依赖与约束。

第7项采用有记录的调整机制，但调整前必须说明后果、强调严格执行当前列表的重要性，并通过30秒暂停给用户重新考虑的机会。具体触发范围、后台与刷新行为、数据兼容和逐项验收以交接文档为准。

该文档是待实施的产品设计，不代表业务功能、安装包或生产部署已经完成。后续任务须结合最新代码核对，不能以已有字段或旧说明代替完整验收。

后续实施逐批记录在 [计划执行与反馈实施记录](../product/2026-10-22-计划执行与反馈实施记录.md)，包含实际范围、验证证据、剩余需求和部署命令。第一批从数据保护与启动条件开始，不代表其余能力训练及30秒调整流程已经完成。

## 2026-10-20：独立判断与主动改进

用户希望协作者有自己的判断，能够挑战用户想法、补充遗漏，提出并落实更好的方案。不要一味顺应，也不要刻意争辩；用具体理由、证据和替代方案推进目标。有重要歧义或不可逆取舍时先对齐，已授权范围内的合理实现选择主动完成。

修改前先用中文说明理解、范围、遗漏和设计。新增约定同步写入本手册与 AGENTS.md。交付区分本地提交、GitHub 推送、服务器部署和真实验证结果。

生产部署由用户执行，提供 Windows PowerShell SSH 登录命令和 Ubuntu 完整更新、构建、健康检查命令。业务数据在服务器保存，本地验证只使用内存数据库或专用测试数据。

## 2026-10-21：本地项目目录与安装包清理

`D:\projects` 专门存放独立项目，书然只保留 `D:\projects\reading-feedback-app` 一个常驻工作目录。日常任务优先使用主项目目录；确需临时工作树时，完成后核对未提交改动与分支提交，再移除或归档，不在 C 盘或 `D:\projects` 留下书然副本。测试脚本、截图等资料归入 `D:\UserData\ProjectArtifacts\reading-feedback-app`，个人文件放到对应的用户资料目录。其他独立项目与个人数据不能仅凭名称或目录数量删除。

APK 确认已上传发布且可下载后，清理本地 APK 与构建副本；保留需要的源码、版本元数据和签名材料，生产服务器上的安装包由部署流程单独维护。`releases/shuran-windows.exe` 是用户日常使用的本地桌面程序，必须保留；其他 Windows 安装文件逐项核对用途。

## 2026-10-21：深度复盘与人工开通

书然面向个人项目与生活管理用户，付费价值是软件生成的深度复盘。免费保留完整记录、计时、日报和周报、历史查看及本人数据导出；有效付费套餐开放月报、季报、年报、跨期对比、阅读主题等深度分析，以及长期目标页的复盘目标与消费预算。项目目标的创建仍免费；消费分类的记录与日、周分类汇总仍免费。
